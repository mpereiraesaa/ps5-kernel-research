# 04 — Forward route on FW 12.02 (TL;DR)

## Hard boundaries — do not spend time here

- Kernel `.text` read/write (NPT xotext bit 58) — no text kpatch, no code
  cave, no runtime text dump.
- HV entry — all ≤7.61 routes (IOMMU write, `hv_unmap_pt_tmr` abuse,
  APICBASE-MSR stack hijack) are dead on this FW.
- Free MSR/CR manipulation (MSRPM + CR interception; EFER
  nda/SVME/NXE writes silently masked).
- Empirically "probing" the NPT with a write to a protected target —
  crash-risk (kernel panic), not a clean error; only inside a dedicated,
  owner-approved console session.

## Foundation we already own

- Kernel data R/W (SDK pipe primitive) — everything RW-mapped in the
  kernel's view, incl. other processes via `vmspace`.
- Full page-table access — 4-level walk via `dmap`, PTE build, guarded
  alias mapping (ps5debug-NG `TSE_ALIASING` model), UELF-style custom
  CR3.
- Gadget-chain ring-0 execution (kstuff per-FW validated entries).
- elfldr 9021 payload loading; Lapy owned-root elevation; ps5debug-NG
  process/kernel debugging.

## Keep moving, in order

1. **Own kernel-data dump** — gate every page through a guest page-table
   walk first and only `kernel_copyout` pages whose leaf PTE is present
   (and cacheable); record everything else as a hole. Then derive
   IDT/GDT/TSS/allproc/rootvnode locally with structural-signature
   scanning and verify the SDK/kstuff/ps5debug-NG tables against live
   structure (Lapy-preflight style). Reproducible evidence; no
   dependence on private dumps.
   - **Done 2026-10-08 within the 64 MiB image window** (see
     `07-evidence.md`): PTE-gated dump (ps5debug-NG `ptw_discover` port;
     pmap pair at `vmspace+0x308`, `dmap=0xffffa39900000000`), zero
     holes, derived IDT/GDT/TSS/kernel_pmap_store offsets, verified
     allproc + security-flags state [verified-on-console].
   - **Constraint learned 2026-10-08 (two kernel-down events, see
     `07-evidence.md`): the loader-pipe `kernel_copyout` is NOT
     fault-tolerant on unmapped pages — and some PTE-present,
     cacheable page in (64, 134] MiB of the window is fatal to it too
     (mechanism unidentified). PTE-gating is mandatory; the 64 MiB
     image window is the proven-safe bound; probing further costs one
     reboot per attempt and needs a deliberate session.**
   - **Open**: rootvnode independent cross-derivation (needs kernel-heap
     namecache strings beyond the safe window); SDK value remains
     `[verified-in-tree]`.
2. **Ship the guarded alias engine** — productize `TSE_ALIASING`-style
   physical-page mapping (guarded PTE write + guard-miss fallback) as the
   standard "read any process at DRAM speed" tool. Biggest unexploited
   multiplier for debugging (prospero-win targets, modding).
3. **Data-flag patches only** — any new "jailbreak-level" toggle =
   `security_flags`-style data edits (`kpatch` model). Never attempt
   text writes.
4. **Gadget chains on demand** — a new privileged op (CR0/MSR/DR access)
   = extend the kstuff per-FW validated-gadget model; never assume an
   unvalidated entry.
5. **Keep the stack consolidated** — single SDK install
   (`ps5debug-NG/ps5-payload-sdk/install/`), `ps5log/1` telemetry on
   every payload, offsets from our own dump + public tables, FreeBSD 11
   source as structural oracle.
