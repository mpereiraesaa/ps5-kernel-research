**⚠ SUPERSEDED 2026-10-12**: The Phase A/B program is archived. The HCALL
0x0f resume-window AP launch remains the research objective, but the FW
12.02 exception-delivery/continuation port is unvalidated (`17` and the

semantic-map work (Phase A) and text-read route survey (Phase B).

Goal restated 2026-10-08 (owner): locally decompiled, semantically mapped
kernel + eventually the HV, via our own capabilities only. Two phases.

## Phase A — semantic kernel map (grow continuously; no text bytes needed)

1. **DONE** — foundation: PTE-gated dump, alias reader, derived offsets
   (see `07-evidence.md`; IDT/GDT/TSS/kernel_pmap_store reproduce across
   boots and match kstuff's public `12_02.h` exactly — three-source
   triangulation with the SDK table).
2. **Historical scan, corrected later** — the initial dump scan at
   `sysents (kdata+0x1af4d0)` reported **746** entries and derived
   target counts from that range. The later declared `sysentvec` size
   and cross-dump comparison use **735** entries (`11` #30; `16`
   §“Cross-dump code-gadget candidates”). The old 470/396 derived
   target counts are not carried forward as validated totals.
3. Label the remaining big pointer tables (34 found; cdevsw / vnodeopv /
   driver ops shapes — each entry named via FreeBSD 11 struct semantics).
4. Cross-FW delta arithmetic over kstuff's public per-FW headers
   (1.00→13.60): same-symbol movement between adjacent FWs encodes
   function sizes and layout.
5. Neighborhood inference: same-`.o` functions are text-adjacent;
   anchors imply neighbors.
6. Mine the 7,595 unlabeled text pointers from the dump (cluster →
   identify table type → label).
7. Optional: call-oracle probing via ps5debug-NG kernel-call mechanisms.

## Phase B — historical text-read survey (no current run plan)

- **GPU/GPUVM text read** [public-consensus; verified-on-console;
  verified-in-tree; retired for FW 12.02]: the public physical-access
  example first patches the IOMMU and supports only older firmware.
  Our 12.02 v1/v2 probes never issued a text DMA request, and v3 was
  blocked offline. There is no evidence of a usable 12.02 path (`07`
  §“gpuvm v1 run” through §“gate upgrade”; `11` #81).
- **MSRPM coverage** [unexplored]: the HV's MSR permission bitmap —
  which MSRs are unintercepted or weakly validated in exit handling.
- **Hypercall validation surface** [unexplored]: the kernel→HV service
  calls (`hv_*`): argument-validation gaps of the class that killed the
  `hv_unmap_pt_tmr` route on 5.x–6.x.
- **HV intercept handlers** [public-consensus attack surface]: the HV
  itself reads kernel text in specific intercept handlers — those paths
  are reachable from guest state by definition.
- **Speculative-execution reads** [hard research]: cache-timing
  exfiltration of NPT-denied pages on the Zen 2 core.

## Hard boundaries — do not spend time here (unless Phase B opens them)

- Kernel `.text` read/write via guest CPU accesses (NPT xotext, bit 58).
- HV entry via the three known routes (IOMMU write, `hv_unmap_pt_tmr`
  abuse, APICBASE MSR hijack) — all closed on 12.x.
- Free MSR/CR manipulation (MSRPM + CR interception; EFER
  nda/SVME/NXE writes silently masked).
- Pipe-primitive reads of unknown-mappedness memory (panics; the alias
  reader is the safe instrument).
